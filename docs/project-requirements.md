# SES案件・人材AIマッチングシステム

SES営業における案件・人材情報の一元管理、精密検索、AIマッチング、営業活動の可視化を目的とした社内向けシステム。

## 1. プロジェクト概要

本プロジェクトは、SES（システムエンジニアリングサービス）営業における案件情報とエンジニア人材情報を一元管理し、候補者の検索・比較・提案業務を効率化するためのシステム開発を目的とする。

現状、案件・人材情報はExcel等で管理されているほか、他社からメールで送付されることも多く、営業担当者が手作業で情報を整理・照合している。

本システムでは、これらの情報を統一された形式で管理し、必須条件による絞り込みとスキル・経験等に基づくマッチングを実現する。

また、マッチング結果に対して一致条件や不足条件、判定根拠を提示することで、営業担当者の意思決定を支援する。

**本システムは候補抽出・推薦を支援するツールであり、最終的な提案可否は営業担当者が判断する。**

## 2. 開発目的

主な目的は以下のとおり。

- **業務効率化**：案件・人材情報の登録、検索、照合作業を効率化する。
- **精密検索の実現**：スキル、経験年数、単価、稼働時期、勤務地などの条件から候補を抽出する。
- **マッチング精度の向上**：必須条件と任意条件を区別し、適合度に基づいて候補を順位付けする。
- **判断根拠の可視化**：一致条件・不足条件・除外理由・スコア内訳を表示する。
- **営業活動の支援**：候補選択、提案、面談、見送り理由などを記録し、進捗管理に活用する。
- **営業効果の可視化**：候補提示数、提案数、面談数などの指標から業務改善につなげる。

## 4. 主要機能

### 4.1 案件情報管理

案件情報の登録・編集・検索・無効化を行う。

想定する主なデータ項目：

- 案件ID・案件名
- 業務概要
- 必須スキル・尚可スキル
- 参画開始日・期間
- 勤務地・勤務形態（常駐／リモート等）
- 単価幅
- 商流
- 面談回数
- 募集人数
- 案件ステータス
- 情報源・最終更新日時

Excel・CSVによる一括取り込み、およびメール由来の案件登録を検討する。

### 4.2 人材情報管理

エンジニアのスキルや稼働条件を登録・管理する。

想定する主なデータ項目：

- 人材ID
- 職務経歴・担当業務
- 保有スキル・経験年数・経験内容
- 資格
- 稼働可能日
- 希望単価
- 希望勤務地・勤務形態
- 所属・契約区分
- 稼働状況
- 情報源・最終更新日時

人材情報については、Excel形式のスキルシートやメールによる受信が想定される。

具体的な入力形式・取り込み方法は今後決定する。

なお、JavaとJavaScriptなど、名称が似ている異なる技術は別スキルとして管理する。

### 4.3 データ取り込み

案件・人材情報の登録方法として、以下を検討する。

- 画面からの手入力
- Excel・CSVの一括インポート
- メール情報からの登録候補生成
- AIによる非構造化データの抽出・構造化

メール取り込みについては、OutlookとPower Automateを組み合わせ、メール情報をCSVまたはJSONとして出力する方式を候補とする。

出力されたデータをPythonで読み込み、必要に応じてローカルLLMで解析する。

**メール連携方式、添付ファイル対応、自動取り込みの有無については未確定。**

また、大量の過去メールを一括取り込みする場合と、日々の新着メールを取り込む場合は処理を分離する方針とする。

### 4.4 精密検索・マッチング

案件または人材を起点として、条件に適合する候補を検索する。

マッチングは次の2段階で実行する。

**第1段階：必須条件による絞り込み**

- 必須スキル
- 稼働可能時期
- 勤務地・勤務形態
- 単価条件
- その他の必須条件

必須条件を満たさない候補は、順位付け対象から除外する。

**第2段階：適合度の算出・順位付け**

- スキル一致度
- 経験年数・経験内容
- 参画時期の適合度
- 単価条件の適合度
- 勤務地・勤務形態
- 尚可スキルの充足状況

条件ごとに重み付けを行い、総合スコアに基づいて候補を表示する。

初期実装では、**説明可能なルールベースのマッチング**を採用する。

将来的には、Embeddingによる意味検索やローカルLLMによる文脈解析を補助的に活用する。

### 4.5 マッチング結果の可視化

候補ごとに以下の情報を表示する。

- 総合マッチングスコア
- 条件別のスコア内訳
- 一致している条件
- 不足している条件
- 確認が必要な条件
- 候補からの除外理由
- マッチング実行日時・実行者

単なる文字列一致ではなく、技術名の正確な識別や、職務経歴の文脈を考慮できる設計を目指す。

AIの出力結果は判断材料として扱い、最終判断は営業担当者が行う。

### 4.6 営業活動管理

マッチング結果を確認した後の営業活動を記録する。

想定する管理項目：

- 候補選択・検討状況
- 提案履歴
- 面談状況
- 見送り理由
- 担当者・コメント
- 操作・更新日時

これにより、重複提案の防止、営業進捗の確認、活動履歴の振り返りを可能にする。

### 4.7 ダッシュボード・効果測定

案件・人材の登録状況や営業活動の成果を可視化する。

想定する指標：

- 登録案件数・登録人材数
- マッチング実行件数
- 候補提示件数
- 提案件数
- 面談件数
- 提案率・面談化率
- その他の営業推進指標

具体的な集計指標や計算方法は、利用者ヒアリングを通じて確定する。

### 4.8 ユーザー・権限管理

社内利用を前提として、ユーザー・役割ごとの権限管理を実装する。

- ログイン認証
- ユーザー管理
- 閲覧・編集権限の制御
- 顧客情報・個人情報へのアクセス制限
- 操作履歴・更新履歴の記録

## 5. 想定業務フロー

1. 案件・人材情報を手入力またはファイルから取り込む。
2. システム内でデータを構造化・保存する。
3. 営業担当者が案件または人材を選択する。
4. 単価・時期・スキル・勤務地などの検索条件を指定する。
5. 必須条件に基づいて候補を絞り込む。
6. 任意条件を加味してマッチングスコアを計算する。
7. 候補をスコア順に表示し、判定根拠や不足条件を確認する。
8. 担当者が候補を比較し、提案可否を判断する。
9. 提案・面談・見送りなどの営業活動を記録する。
10. 蓄積したデータを用いて検索条件やマッチングロジックを改善する。

アプリケーションの配置場所、AIモデルの実行環境、データの保存先については、要件定義後に決定する。

## 7. AI活用方針

AIは主に以下の用途で活用を検討する。

**① 非構造化データの解析**

メール本文やスキルシート等から、案件・人材情報を抽出し、統一形式に変換する。

**② スキル・職務経歴の文脈理解**

スキル名称の単純一致では判定できない関連技術や経験内容について、必要に応じてAIによる補助判定を行う。

ただし、JavaとJavaScriptのような別技術を誤って同一視しないよう、技術マスタや正規化ルールを優先する。

**③ マッチングの補助**

初期段階ではルールベースのスコアリングを採用し、将来的にEmbeddingやAIを活用した候補検索・推薦精度の改善を検討する。

AIが提案可否を自動決定することは想定しない。

## 8. 非機能要件・セキュリティ

### 8.1 情報保護

- 案件・人材情報に対するアクセス権限を設定する。
- 氏名などの個人情報は必要最小限の範囲で保持する。
- AI解析に伴う外部サービスへのデータ送信を制限する。
- 通信および保存データの保護を検討する。
- 機密情報をログやソースコードに不用意に出力しない。

### 8.2 データ管理

- データの情報源・更新日時を保持する。
- 古い案件・人材情報を識別できるようにする。
- 重複登録や誤登録を防止する。
- データの訂正・無効化・削除を可能にする。
- 保存期間・バックアップ・復旧方法を定める。

### 8.3 性能・運用

初期検討において、過去約10万件のメールを扱う可能性がある。

そのため、大量データの取り込み・解析については、非同期処理やバッチ処理を検討する。

また、新着メールについては、**受信から5分以内に解析を完了し、マッチングに利用可能な状態にすることを初期の性能目標**とする。

ただし、メール連携方式・実行環境・AI処理性能によって実現可能性が異なるため、PoCによる検証を行ったうえで正式な性能要件を定める。

## 10. 開発方針・進め方

本プロジェクトでは、要件定義後にMVPを構築し、実際の営業担当者からのフィードバックをもとに段階的に改善する。

### Phase 1：要件定義・基本設計

- 業務フロー・データ項目の確定
- マッチング条件・スコアリング基準の検討
- データ取り込み方式の決定
- インフラ・セキュリティ方針の決定

### Phase 2：画面モック・PoC

- 画面モックの作成・レビュー
- Excel / CSVの取り込み検証
- Power Automateによるメールデータ出力検証
- ローカルLLMによる構造化抽出検証
- ルールベースマッチングの検証

### Phase 3：MVP開発

- 案件・人材管理
- 検索・マッチング
- 判定根拠の表示
- 候補比較・営業活動記録
- ユーザー・権限管理

### Phase 4：評価・改善

- 検索・マッチング精度の検証
- 大量データ取り込みの性能検証
- 営業業務の効率化効果を測定
- AI活用範囲・スコアリングロジックの改善

## 12. 今後の展望

初期段階では、案件・人材情報の一元管理と、説明可能なルールベースマッチングの実現を優先する。

その後、営業担当者の利用状況やフィードバックに基づき、AIによるデータ解析・意味検索・マッチング精度の向上を段階的に検討する。

最終的には、SES営業担当者が大量の案件情報やスキルシートを個別に確認する負担を減らし、**適切な案件と人材を、より速く、根拠を持って提案できる営業支援基盤**の構築を目指す。
